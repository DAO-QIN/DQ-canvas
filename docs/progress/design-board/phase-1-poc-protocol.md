# Phase 1 执行协议：编辑器引擎与许可证 PoC

状态：已执行；Gate 结论见 `phase-1-gate-report.md`，完成后停止等待 Phase 2 确认
目标：用同一商品图设计场景实测 tldraw 5.2.5 与 Fabric.js，选择一个且仅一个 P0 编辑器引擎
边界：不挂正式导航、不写数据库、不调用真实 AI、不消耗积分、不部署线上

## 1. 阶段产物

Phase 1 必须交付以下可复核产物，缺一不可：

1. 两个相互隔离、使用相同领域夹具和测试动作的 PoC。
2. 自动化契约测试、导出像素测试与至少一条真实浏览器操作流。
3. tldraw 5.2.5 生产授权证据和 DQ 本地补丁影响说明。
4. Fabric.js 版本、许可证、包体和 DQ 集成说明。
5. 原始数据、截图、浏览器控制台结果和 `phase-1-scorecard.md`。
6. `phase-1-gate-report.md`，明确 `PASS`、`FAIL` 或 `BLOCKED BY LICENSE`。
7. 更新 `architecture-decisions.md` 的 ADR-004 和 `source-reuse-register.md` 的实际使用记录。

PoC 不是最终 UI，不得借机实现数据库、正式项目列表、Agent 或 AI 生成。

## 2. 隔离结构

确认进入 Phase 1 后，优先新增以下范围；执行前仍需重新检查目标文件 Git 状态：

```text
web/src/features/design-engine-poc/
|- contract/                 # 引擎无关的 fixture、断言与 Design Ops 草案
|- tldraw/                   # tldraw 单引擎适配
|- fabric/                   # Fabric.js 单引擎适配
`- components/               # 仅供比较页使用的指标与控制 UI

web/src/app/(user)/design-poc/
`- page.tsx                  # 登录保护、无导航入口、环境开关保护

web/e2e/design-engine-poc.spec.ts
web/public/design-poc/       # 仅存无版权风险的测试素材
```

比较页必须满足：

- 只有 `DQ_DESIGN_POC_ENABLED=1` 时可访问，否则 `notFound()`。
- 不加入 `navigation-tools.ts`，不出现在正式入口、站点地图或产品文案中。
- 不发起任何项目保存、数据库、生成任务、积分或外部模型请求。
- tldraw 和 Fabric 各自持有独立 Store；页面一次只挂载一个引擎，避免比较页本身造成双引擎内存干扰。
- 两个适配器实现同一最小接口，测试不得绕过接口直接操纵某个引擎。

建议最小接口：

```ts
type DesignEnginePocAdapter = {
  load(document: DesignPocDocument): Promise<void>;
  exportDocument(): DesignPocDocument;
  apply(operations: DesignPocOperation[]): DesignPocOperationReceipt;
  getSelection(): string[];
  setSelection(ids: string[]): void;
  exportFrame(
    frameId: string,
    options: { scale: 1 | 2; format: "png" | "jpeg" },
  ): Promise<Blob>;
  getMetrics(): DesignPocMetrics;
  destroy(): void;
};
```

这只是 PoC 适配接口，不是 Phase 2 的最终 Design Document API。不得为了让某个引擎通过而给另一方使用更弱的断言。

## 3. 统一商品图夹具

### 3.1 Frame

同一文档包含 4 个彼此分离的 Frame：

| ID                   | 场景           | 像素尺寸    | 背景                   |
| -------------------- | -------------- | ----------- | ---------------------- |
| `frame-amazon-main`  | Amazon 主图    | 2000 × 2000 | 白色                   |
| `frame-amazon-aplus` | Amazon A+ 横幅 | 1464 × 600  | 浅灰                   |
| `frame-social-feed`  | 社媒竖图       | 1080 × 1350 | 品牌渐变或等价纯色夹具 |
| `frame-social-story` | Story 广告     | 1080 × 1920 | 深色                   |

Frame 必须有稳定 ID、名称、像素尺寸、层级和导出设置。Workspace 坐标不等于导出像素；改变相机缩放不能改变导出结果。

### 3.2 素材

Phase 1 新建、可提交且无外部版权风险的夹具：

- `product-transparent.png`：3000 × 3000、透明背景、带不对称方向特征，便于判断裁剪和翻转。
- `product-background.jpg`：3200 × 2400，含规则网格和四角编号，便于验证裁剪坐标。
- `brand-mark.svg`：简单几何测试标，无 DQ 或第三方商标。
- 中英文文字：`DQ Bottle / 轻盈一整天`，包含 ASCII、中文、数字与标点。

测试素材禁止使用 Lovart、Jaaz、Loomic 或研究仓库的品牌图、字体和示例资产。字体只使用仓库已有或系统明确可用的测试字体；字体缺失必须显示可观察的 fallback，不能静默改变文档测量。

### 3.3 元素规模

基础夹具至少包含：

- 4 个 Frame。
- 每个 Frame 各 2 张图片、2 段文字、3 个基础图形。
- 1 个跨 Frame 的多选测试集合。
- 1 张旋转 17° 的图片。
- 1 张非破坏裁剪图片，裁剪框比例为 4:3。
- 1 个锁定元素和 1 个隐藏元素。
- 1 个含中文的多行文字元素。

性能夹具在基础夹具上复制到 200 个可见元素，但资源仍按稳定引用去重，不嵌入 base64。

## 4. 完全相同的操作脚本

两个引擎必须按以下顺序运行并记录每步结果：

1. 载入基础文档并适配全部 Frame 视图。
2. 选择 `frame-amazon-main` 中的商品图，移动 `(40, 30)`、缩放到 `0.75`、旋转到 `17°`。
3. 把商品图向前移动一层，确认锁定背景不被改变。
4. 对背景图设置归一化裁剪区域 `{ x: 0.125, y: 0.1, width: 0.75, height: 0.8 }`。
5. 修改中英文标题的字体族、字重、字号、行高、字距和对齐方式。
6. 多选 3 个元素，执行水平居中与等距分布。
7. 复制一个图文组合到 `frame-social-feed`，生成新稳定 ID，资源引用保持复用。
8. Undo 7 次，再 Redo 7 次，检查文档语义和选择状态。
9. 导出规范化 DesignPocDocument，销毁引擎，重新初始化并载入。
10. 再次导出并做忽略非语义运行字段的深比较。
11. 对 Amazon 主图分别导出 1x PNG、2x PNG 和 1x JPEG。
12. 载入 200 元素夹具，执行 30 秒平移/缩放/选择/拖动并采集指标。
13. 执行一批含合法、未知 ID、越界尺寸和非法类型的 Design Ops，检查原子/部分失败策略与回执。

不能用截图相似替代文档语义断言；也不能只比较 JSON 字符串顺序。

## 5. 硬门槛

任一项失败，该引擎不得成为 P0 首选：

| Gate            | 通过标准                                                                                            |
| --------------- | --------------------------------------------------------------------------------------------------- |
| G1 生产许可     | 有适用于 DQ 实际部署和用户规模的许可证证据；需 Key 时有采购/配置路径。模板许可证不能替代 SDK 许可证 |
| G2 单引擎       | 不依赖在 Frame 内再嵌套另一画布引擎完成裁剪、文本或导出                                             |
| G3 单一真源     | 元素树只有一个可写 Store；React/Zustand 不维护可独立修改的镜像文档                                  |
| G4 文档恢复     | 连续 10 次 export → destroy → load 后，稳定 ID、Frame、层级、裁剪、文本和资源引用语义一致           |
| G5 精确导出     | 1x PNG 为 2000 × 2000，2x PNG 为 4000 × 4000；相机缩放不影响像素尺寸，透明区和裁剪边界正确          |
| G6 资源安全     | 文档中不存在 `data:`、`blob:`、对象存储 Key 或临时签名 URL；导出时按受控资源解析器读取              |
| G7 历史一致性   | 7 次 Undo/Redo 后文档与预期逐步一致；异步资源加载不制造幽灵历史项                                   |
| G8 稳定对象引用 | 选中、图层、属性面板和 Design Ops 使用同一稳定元素 ID                                               |
| G9 生命周期     | 切换或销毁引擎后无残留全局监听器、计时器、Worker 或重复 Store 订阅                                  |
| G10 DQ 回归     | TypeScript、ESLint、相关单测通过；现有 `/canvas` 专项测试不回退                                     |

若 tldraw 仅 G1 尚未得到证据，其技术结果标为 `TECHNICAL PASS / BLOCKED BY LICENSE`，不能通过总 Gate。Fabric 若能满足全部硬门槛，则必须保留为可落地选择。

## 6. 评分表（硬门槛通过后才计分）

总分 100；每项保留原始测量证据，不允许只填主观 1–5 分。

| 维度             | 权重 | 主要证据                                                         |
| ---------------- | ---: | ---------------------------------------------------------------- |
| 商品图编辑能力   |   20 | Frame、图片、文字、裁剪、图层、对齐、吸附完成度与额外代码量      |
| 文档与历史可靠性 |   15 | 10 次往返、Undo/Redo、稳定 ID、非法文档行为                      |
| 导出质量         |   15 | 像素尺寸、透明度、裁剪、文字、1x/2x、耗时和峰值内存              |
| DQ 平台集成      |   15 | React 19/Next 16、现有资源 URL、主题、快捷键、Agent Ops 适配成本 |
| 性能与生命周期   |   10 | 200 元素交互、首次加载、切换销毁、监听器和内存趋势               |
| 可扩展性         |   10 | 自定义元素、对象引用、上下文提取、未来协作/评论边界              |
| 工程与维护成本   |   10 | 新依赖、补丁、私有 API、代码量、测试难度、升级风险               |
| 许可与合规成本   |    5 | Key、费用/限制、NOTICE、源码复用追踪和部署约束                   |

计分规则：

- 每个维度按 `0–5` 打原始分，维度得分为 `权重 × 原始分 / 5`。
- 无自动化或可重复证据的主观结论最高只能得 2 分。
- 使用引擎私有/下划线 API 实现核心能力，该维度最高 3 分，并登记升级风险。
- 同分时依次比较：硬门槛余量、导出质量、文档可靠性、维护成本。
- 推荐线为 75/100，且领先另一候选至少 5 分；差距小于 5 分时，优先选择许可证更清晰、私有 API 更少、DQ 改动面更小者。

## 7. 性能与导出记录

在同一浏览器、同一构建模式、同一视口、同一素材缓存状态下各运行至少 3 次，报告中保留中位数和最差值：

- 引擎 JS/CSS 增量体积。
- 基础文档首次可交互时间。
- 200 元素下平移、缩放、选择和拖动的长任务数量与最长任务。
- 10 次引擎初始化/销毁后的 JS heap 趋势；浏览器不支持精确 heap 时明确标为缺失，不能猜测。
- 2000 × 2000 与 4000 × 4000 PNG 导出耗时、Blob 大小和像素尺寸。
- DesignPocDocument JSON 字节数；图片只能保存稳定引用。

建议目标而非伪造硬限制：200 元素常规拖动不出现连续卡死，单次交互长任务尽量低于 50ms；4K 导出不能让页面永久无响应或静默输出降分辨率。未达到时报告真实测量和根因。

## 8. 许可证核验清单

### tldraw 5.2.5

- 固定 npm 包版本、包内许可证指针、对应上游 tag/commit 和核验日期。
- 区分 `tldraw/agent-template` 的 MIT 与 tldraw SDK 的独立许可证。
- 确认 DQ 的生产域名、部署方式、用户/开发者规模是否落在授权范围。
- 确认是否必须配置 license key、如何注入、过期/失效时行为，以及开发/测试/生产是否不同。
- 审计 `web/patches/@tldraw__editor@5.2.5.patch` 是否被许可、是否影响升级或支持。
- 不在文档、日志或测试快照中记录真实 Key。

### Fabric.js

- 固定 PoC 使用版本和上游 commit/tag。
- 核对 MIT 许可证、版权声明和依赖许可证。
- 确认所用裁剪、滤镜、字体和导出能力不依赖未授权的第三方插件/素材。
- 把真实新增依赖写入 `web/package.json` 和 `web/pnpm-lock.yaml`，不更新 `web/package-lock.json`。

许可证无法从公开证据确认时，报告“需要项目所有者提供采购凭证或供应商确认”，不把用户对本项目的复制授权冒充上游许可。

## 9. Phase 1 停止条件

出现以下任一情况，立即停止扩展该候选并记录证据，不用更多功能掩盖根因：

- 必须采用 tldraw + Fabric 双引擎才能满足 P0。
- 导出尺寸或文档恢复连续 3 次修正仍失败，且根因指向引擎硬限制。
- 核心实现只能依赖不稳定私有 API，且没有可维护的公开扩展点。
- 许可证明确禁止或无法覆盖 DQ 的预期生产使用。
- 引擎会破坏现有 `/canvas` 使用的 tldraw 版本/补丁，且无法通过隔离解决。
- 为 PoC 必须先修改数据库、计费、真实生成或线上部署。

一个候选停止不代表 Phase 1 失败；继续完成另一候选的证据闭环。只有两个候选都触发硬阻断，才提出第三候选 Konva，并输出新的、经过确认的 PoC 范围。

## 10. 执行顺序与 Gate

1. 再次记录 Git 状态、Node/pnpm、依赖和许可证基线。
2. 创建引擎无关的契约、测试素材生成脚本和断言。
3. 实现 tldraw 适配并运行统一脚本。
4. 实现 Fabric 适配并运行同一脚本。
5. 在 Node 22、pnpm 10.34.5 下重复类型、单测、浏览器和导出验证。
6. 只对 Phase 1 改动文件做定向 Prettier；同时报告全仓已知格式偏差是否变化。
7. 完成评分、许可证结论、源码复用登记和 Phase Gate Report。

Phase 1 只有在以下条件同时成立时为 `PASS`：

- 至少一个候选通过 G1–G10。
- 推荐候选达到评分线，证据可重复。
- 没有正式产品、数据库、生成任务或积分副作用。
- 现有 `/canvas` 专项回归通过。
- ADR-004 已更新为单引擎选择，并写明放弃另一候选的证据。

Gate PASS 后仍须停下，等待确认进入 Phase 2，不得直接创建 `design_projects`。
