## 结构性判断

- `DesignDocument.layers`、Store、typed Ops、FIFO persistence 和 Fabric projection 的职责边界保持清晰，没有为历史或图层引入第二份文档状态。
- 历史快照只是生成目标差异的运行时证据；Undo/Redo 仍是新的持久事务，因此 revision、并发冲突和回执语义没有被绕过。
- 对齐/分布被实现为纯命令生成器，避免新增领域 Op；这符合“动作组合可以由现有原子语义表达时，不扩张 Schema”的原则。
- 跨 scope 坐标换算集中在纯命令中，Fabric 仍只提交场景手势意图，读写边界明确。

## 下次重点关注

- Phase 8 真实图片代理加载、所有权和签名 URL 生命周期必须先冻结协议再接 Fabric。
- 裁剪应保持归一化 `crop`，预览状态与保存 Op 分离；不能用 Fabric clipPath 反向序列化文档。
- 对大批量历史恢复要持续监控 `maxOperationsPerBatch`；超过上限必须显式拒绝或设计服务端事务协议，不能拆成非原子批次伪装成功。

### 做得好的地方

- 先用 Fabric 7 源码确认 transform 每帧已经调用 `requestRenderAll()`，再删除适配器重复重绘，结论可追溯。
- 优化没有把 Fabric 升格为第二状态真源，也没有改成拖动期间频繁保存；每次真实手势仍只在松手后提交一个 typed transform revision。
- 生产部署保留 `dq-new:phase7` 和 Phase 6 镜像；只重建 app/worker，PostgreSQL、rembg 与持久卷原位不动。
